01The problem

Releases keep coming. Training time doesn’t grow with them.

Appian now ships a release every month. The 26.10 release notes alone list 49 changes across 17 product areas, from new AI capabilities to a new color option for links.

Release notes say what changed. They rarely say who needs to learn it, or how.

A small learning team has to decide, every month, what deserves a full launch, what needs a short update for existing users, and what needs nothing at all.

03My triage rules

Three tiers, three outputs.

Tier 1

Strategic

Full launch package

Any one of: a new capability for a key audience, a marketing priority, or a big change to how people build.

Output

Feature video, in-product guide, and course

Tier 2

Notable

Delta card

Changes what an existing user must know or do: a renamed setting, changed behavior, a deprecation that needs action, a useful new option.

Output

What changed, why it matters, try it, check yourself

Tier 3

Minor

Release note only

Needs no new knowledge or action: cosmetic options, performance gains, new model versions, automatic upgrades.

Output

Nothing beyond the release note

04Standard formats

In-product guide, standard format.

Every guide follows the same short sequence, so learners always know where they are and reviewers always know what to check.

  1. Slide 01

    What it is and why

    Explains the feature and why it matters to this learner.

  2. Slide 02

    Where to find it

    Points to the exact place in the product to start.

  3. Slide 03

    Try it

    One small, real action the learner can take right now.

05Sample output

A delta card, drafted by Claude, verified by me.

Delta card · Data fabric

Notable · Appian 26.6 → 26.10

Synced or unsynced record types?

What changed

  • 26.6–26.10Unsynced record types gain most data fabric features, including relationships, custom record fields, and record-level security.
  • 26.10Record types allow up to 500 fields (up to 50 custom record fields), up from 100.
  • 26.10Move all dependent record types to a new data source in one step, with a validation check first.

Why it matters

Unsynced record types now support most data fabric features for Databricks, MariaDB, MySQL, Oracle, PostgreSQL, Snowflake, and SQL Server. They are a real option for very large or fast-changing data.

Synced is still the recommended default for most applications. It is the only way to get smart search, Process HQ process analysis, sync filters, and sync-time custom record fields. Unsynced has no row limit and no text length limit, but its speed depends on the source system.

Try it: the decision rule

Start with synced. Choose unsynced only when one of these is true:

  • The data changes outside Appian, you need changes immediately, and syncing isn’t an option.
  • The data exceeds your tier’s row limit (4 million rows on standard, 20 million on advanced), even after sync filters.
  • You need text fields longer than 64,000 characters.

Check yourself 0 / 3

Q1 An HR app with 50,000 employee records, updated mostly through Appian forms.

Q2 A dashboard of prices that change every second in an external system.

Q3 Your team wants process analysis in Process HQ for case data.

06Who did what

Where AI saves time, and where judgment stays human.

Claude

Speed and coverage
  • Read all 49 release entries and grouped related changes
  • Applied my tier rules and listed the close calls
  • Pulled facts and limits from the documentation
  • Drafted the delta card in my standard format

Me

Standards and judgment
  • Wrote the tier rules and the in-product guide format
  • Reclassified three items after review
  • Chose the sample topic and the learner scenarios
  • Verified every claim against the 26.10 documentation

Verification matters because the source can be wrong too.

In the Appian Community, users found that the 26.6 documentation listed a different MCP Server endpoint than the Administration Console, and Appian confirmed the docs needed correcting. Checking drafts against the live product catches problems like that before learners do.
